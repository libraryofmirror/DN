# 서버시간 측정기

신청 버튼을 눌렀을 때 **그 신호가 사이트 서버에 도달하는 시각**을, 그 사이트의 서버 시계 기준으로 알려 주는 도구입니다.

- 대상 사이트의 서버 시각을 밀리초까지 추정해 실시간 시계로 표시
- 클릭한 순간의 서버 시각 → 서버 도달 예상 시각 계산 + 실제 요청으로 검증
- 목표 시각(예: 14:00:00.000)에 신호가 도달하도록 **언제 눌러야 하는지** 카운트다운

## 실행

Node.js 18 이상이면 됩니다. 설치할 의존성은 없습니다.

```bash
cd tools/server-time
node server.mjs                       # 브라우저에서 대상 입력
node server.mjs https://example.com   # 대상을 미리 지정
```

터미널에서 http://127.0.0.1:8787 을 열면 됩니다.

옵션: `--port 9000`, `--host 127.0.0.1`, `--method GET` (HEAD를 막는 서버용)

터미널만 쓰려면:

```bash
node cli.mjs https://example.com
```

동작 검증:

```bash
node test/clock.test.mjs   # 시계를 일부러 틀어놓은 가짜 서버로 추정 정확도 확인
```

## 왜 로컬 프로그램인가

브라우저에서 다른 사이트로 직접 요청하면 CORS 때문에 응답 헤더를 읽을 수 없습니다.
그래서 실제 측정은 이 Node 프로세스가 하고 화면만 브라우저에 띄웁니다.
측정이 **여러분의 회선에서** 이루어지므로 지연 값은 실제 신청 상황과 같습니다.

## 어떻게 밀리초까지 알아내나

HTTP 응답의 `Date` 헤더는 **초 단위**라 그대로 쓰면 오차가 ±500ms입니다.
대신 요청 한 번에서 다음 부등식을 얻습니다.

```
t0 = 요청을 보낸 시각, t1 = 응답 헤더를 받은 시각   (둘 다 내 컴퓨터 시계)
서버가 Date를 찍은 순간은 반드시 t0 이상 t1 이하
Date 값 D 는 그 순간을 초 단위로 버린 값 → 그 순간의 서버 시각 ∈ [D, D+1000)

  offset(= 서버시각 − 내 시각) ∈ [D − t1,  D + 1000 − t0)
```

요청을 촘촘히 반복해 이 구간들을 **교집합**하면, `Date` 값이 넘어가는 초 경계를
사이에 끼고 있는 요청 쌍이 구간을 급격히 좁힙니다. 최종 폭은 대략
`왕복지연 + 요청간격` 수준이고, 화면의 `±` 값이 그 절반(오차 한계)입니다.

이 방식은 편도 지연이 대칭이라는 가정을 하지 않으므로, 표시된 ± 안에 참값이 있음이
보장됩니다. (`test/clock.test.mjs`가 이 성질을 검증합니다.)

정밀도가 확보되면 아무 때나 찌르지 않고 **다음 초 경계 직전에만** 짧게 몰아 요청해
정확도를 유지합니다. 평상시 요청량은 초당 1~2회 수준입니다.

## 클릭 도달 시각

```
서버 도달 예상 시각 = 클릭한 순간의 서버 시각 + 편도 지연
편도 지연 ≈ 최소 왕복지연 / 2        (최소값을 쓰는 이유: 큐잉 노이즈가 가장 적음)
```

버튼을 누르면 그 즉시 실제 요청을 한 번 보내고, 돌아온 응답의 `Date`(초 단위)가
계산된 도달 시각과 같은 초에 들어오는지 대조해 보여 줍니다.

## 주의할 점

- `Date` 헤더는 요청을 **맨 앞에서 받은 장비**의 시각입니다. CDN·로드밸런서 뒤에 있는
  사이트라면 실제 접수 서버와 몇 ms 차이가 날 수 있습니다.
- 응답에 `Age` 헤더가 있으면(캐시된 응답) 그 `Date`는 현재 시각이 아니므로 자동으로
  제외하고 경고를 띄웁니다.
- 브라우저에서 진짜 버튼을 누를 때는 클릭 처리·스크립트 실행·TLS 재개 등으로 여기서
  잰 값보다 몇 ms가 더 붙습니다. "추가 여유(ms)" 입력으로 보정하세요.
- 헬퍼 서버는 기본적으로 `127.0.0.1`에만 바인딩합니다. 외부에 열면 임의의 주소를 대신
  요청해 주는 통로가 되므로 그대로 두는 것을 권합니다.
- 이 도구는 시각을 **측정하고 알려 줄 뿐**, 사이트에 로그인하거나 신청을 대신 제출하지
  않습니다. 대상 사이트의 이용약관은 각자 확인하세요.
