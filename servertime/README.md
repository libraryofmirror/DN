# 서버시간 측정기

신청 버튼을 눌렀을 때, **그 신호가 사이트 서버에 도달하는 시각을 서버 시계 기준 ms 단위로** 알려 주는 도구입니다.
자동으로 눌러 주거나 대신 신청해 주는 기능은 없습니다. 측정과 표시만 합니다.

두 가지로 구성되어 있습니다.

| | 무엇 | 언제 쓰나 |
|---|---|---|
| **측정기 페이지** | `server.py` + `index.html` | 신청 전에 서버 시각을 맞추고, 목표 시각에 맞춰 연습할 때 |
| **오버레이** | `overlay.user.js` | 실제 신청 페이지 위에 띄워, 진짜 신청 버튼 클릭을 측정할 때 |

---

## 1. 측정기 페이지

```bash
python3 servertime/server.py --open
# → http://127.0.0.1:8765/
```

파이썬 3.8 이상이면 되고, 설치할 패키지는 없습니다. 127.0.0.1 에만 열리므로 외부에서 접속할 수 없습니다.

1. 신청 페이지 주소를 넣고 **동기화 시작**
2. 10~20초 지나면 오차가 ±수십 ms 이내로 줄어듭니다
3. **신청 클릭** 버튼을 누르면 누른 순간과 서버 도달 시각이 기록됩니다
4. 목표 시각(예: `20:00:00.000`)을 넣으면 **몇 시 몇 분 몇 초 몇 밀리초에 눌러야 하는지** 알려 줍니다

브라우저는 다른 도메인 응답의 `Date` 헤더를 CORS 때문에 읽을 수 없기 때문에, `server.py` 가 대신 요청을 보내
요청·응답 시각과 `Date` 헤더를 돌려주는 역할을 합니다. 대상 사이트에는 `HEAD` 요청만 나가며(초당 10회 제한),
`POST` 는 보내지 않습니다.

옵션:

```
-p, --port     포트 (기본 8765)
    --host     바인딩 주소 (기본 127.0.0.1)
    --insecure TLS 인증서 검증 생략 (사내망 등)
    --open     브라우저 자동 실행
-v, --verbose  접속 로그 출력
```

## 2. 오버레이 — 실제 신청 페이지에서

실제로 신청할 페이지에 띄우면, **그 페이지에서 진짜 버튼을 눌렀을 때** 나간 요청이 서버에 닿은 시각을 기록합니다.
같은 출처(same-origin)라서 프록시 없이 혼자 동작합니다.

- **콘솔에 붙여넣기 (가장 확실함)** — 신청 페이지에서 `F12` → Console → `overlay.user.js` 내용을 통째로 붙여넣고 Enter.
  크롬은 처음 한 번 `allow pasting` 을 입력해야 붙여넣기가 됩니다.
- **유저스크립트 매니저** — Tampermonkey 등에 등록하고 `@match` 를 해당 사이트로 좁힙니다.

화면 오른쪽 위에 뜨는 창에서:

- 큰 숫자 = 그 사이트 서버의 현재 시각
- `오차` = 이 시각이 얼마나 믿을 만한지 (± ms)
- `상행(클릭→서버)` = 내 클릭이 서버까지 가는 데 걸리는 시간
- 아래 목록 = 클릭한 버튼과 그 신호가 **서버에 도달한 시각**

버튼이 페이지 이동을 일으켜도 됩니다. 클릭 정보를 저장해 두었다가 다음 페이지에서 도달 시각을 복원합니다.

`window.__serverTimeOverlay.now()` 로 서버 시각(epoch ms)을, `.error()` 로 오차를 얻을 수 있습니다.

## 어떻게 ms 단위까지 알아내나

HTTP 응답 헤더의 `Date` 는 **초 단위로 잘려** 있습니다. 그대로 쓰면 최대 1초가 틀립니다. 대신 이렇게 좁힙니다.

1. 요청을 보낸 시각 `t0`, 응답 헤더를 받은 시각 `t1`, 응답의 `Date` 를 기록합니다.
2. 서버가 그 `Date` 를 만든 순간은 반드시 `t0 ~ t1` 사이에 있고, 잘린 값이므로 실제 서버시간은 `[Date, Date+1초)` 안에 있습니다.
   따라서 시계 차이 `offset`(= 서버시계 − 내시계) 은 이 구간 안에 있습니다.

   ```
   Date − t1  <  offset  <  Date + 1000 − t0
   ```
3. 요청 시점을 **서버의 초가 바뀌는 순간 근처로** 조준해 가며 이 구간을 계속 교집합합니다.
   구간 폭은 왕복 지연 수준(보통 10~40ms)까지 줄어듭니다. 화면의 `±` 가 그 폭의 절반입니다.
4. 가장 많이 겹치는 구간만 골라 교집합하므로, 캐시된 응답이나 순간적으로 튄 샘플이 섞여도 전체가 망가지지 않습니다.

클릭 신호의 도달 시각은 이렇게 계산합니다.

```
서버 도달 시각 = 브라우저가 요청을 내보낸 시각 + 시계 차이 + 상행 지연(왕복 ÷ 2)
```

오버레이는 브라우저의 Resource Timing 에서 `requestStart`(실제로 바이트를 내보낸 시각)를 쓰므로,
자바스크립트 실행 지연이 섞이지 않습니다. 누른 순간 자체는 클릭 이벤트의 `timeStamp`(물리적으로 눌린 시각)로 기록합니다.

## 한계

- **`Date` 는 웹 서버 시계입니다.** 접수를 실제로 처리하는 뒤쪽 서버(DB·큐)의 시계와 다를 수 있습니다.
- **상행 지연은 왕복의 절반으로 가정한 값입니다.** 업로드·다운로드 경로가 비대칭이면 그만큼 어긋납니다.
- CDN·프록시가 캐시된 응답(`Age > 0`)을 주면 그 샘플은 자동으로 버립니다. 계속 경고가 뜨면 캐시되지 않는 주소를 쓰세요.
- 대기열(큐)을 쓰는 사이트는 도착 순서가 아니라 큐 진입 순서로 처리되기도 합니다.
- 정확도는 회선 상태에 좌우됩니다. 유선·안정된 회선일수록 좁아집니다.
- 대상 사이트에 부담을 주지 않도록 요청 빈도가 제한되어 있습니다. 제한을 풀어 쓰지 마세요.
